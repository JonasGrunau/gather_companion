# gather_companion

## Purpose

Two halves of one product, in one repository. **`gather-app-bridge`** (`bridge/`)
is a zero-dependency Node daemon that runs on the computer where the Gather V2
desktop client is open, watches that client, and serves presence events over the
LAN. **Gather Companion** (`lib/`, `ios/`) is the Flutter phone app that consumes
that stream and tells you when somebody starts following you around the space.

Both halves authenticate to Gather as the user and open their own game socket;
neither goes through the desktop client, and neither patches it. What separates
them is what they are allowed to *do* once connected: the bridge only ever reads,
while the app enters the space and publishes media. That split is load-bearing —
see "Working In This Directory" below.

The bridge is published to npm; the app is published to TestFlight. **One git tag
ships both.**

## For AI Agents

### Working In This Directory

- **The event contract is duplicated by design.** `bridge/lib/events.js` and
  `packages/gather_events/lib/src/events.dart` describe the same JSON. Renaming a
  field on one side silently breaks the other — there is no codegen and no schema
  file. Change both, and update the event-type table in `README.md`.
- **The bridge must stay dependency-free.** `install` copies only `bridge/lib`
  and `bridge/bin` into `~/.gather-app-bridge/bridge` and launchd runs that copy
  directly, with no `node_modules` to resolve. Adding an npm dependency breaks
  every installed daemon. This is why msgpack, the WebSocket server and the QR
  encoder are all hand-rolled.
- **The protocol exists twice, and must not drift — with one named exception.**
  `bridge/lib/{msgpack,game-protocol,direct,presence}.js` and
  `packages/gather_client/lib/src/*.dart` are the same wire format in two
  languages, because the app reads Gather itself and the bridge still has to for
  push. Change one, change the other.
  `packages/gather_client/test/msgpack_test.dart` pins the Dart encoder's bytes
  against hex generated by the JS encoder, which is the tripwire: Gather does not
  reject a malformed handshake, it goes silent, so a divergence looks like a
  network fault rather than a bug.
  The exception is the handshake, and it is deliberate: the Dart collector sends
  two frames the JS one must never grow. See the next bullet. Everything else
  still moves in lockstep.
- **The bridge observes. The app participates.** These used to be one rule and
  are now two, because the app publishes audio and video and a thing that
  publishes is present.
  - *The bridge* opens its own authenticated game socket and sends exactly
    `Authenticate`, `ConnectToSpace`, `Subscribe`, one `Action{loadSpaceUser}`
    and a heartbeat. Never `enterSpace`, never a move, a chat or a setting. It
    exists to wake a sleeping phone and has no reason to be in a room.
    `bridge/test/direct.test.js` asserts this and should keep failing anyone who
    tries.
  - *The app* enters: `enterSpace` plus `reportActivity`, then media. What stays
    binding is that it participates **as you and never as a second body** — the
    same account, the same `SpaceUser`, the user's own credential, never a
    fabricated second identity.
  Neither disturbs the user's desktop session. Measured 2026-08-06 against a live
  space: a duplicate `spaceId` + `authUserId` is not evicted with close 4031, and
  an entered connection did not close the desktop socket or move its avatar,
  because `Connection` is per-connection while `SpaceUser` is
  per-person-per-space. Entering is not free, though — `numTimesEnteredSpace`
  increments per entering connection, permanently, on the user's own profile —
  which is why `AppState.verifyLink()` must keep declining to reconnect a healthy
  socket. The desktop client is never patched; `app.asar` is integrity-checked
  anyway.
- **Honesty over confidence.** Where the bridge does not know something it says
  so rather than guessing: `confidence: 'inferred'` vs `'observed'`, and the
  collector reports itself *unhealthy* while connected-but-stateless rather than
  rendering an empty room as "nobody is following you". Preserve that property
  in any change. The same rule is why mic/camera/screenshare were deleted rather
  than left as fields nothing could fill.
- **The README is not decoration.** It records findings that cost real
  investigation (the npm owner-field case sensitivity, the cloud-signing
  failure, the two log id namespaces). Keep it current when behaviour changes.

### Testing Requirements

```sh
npm test                        # bridge: parser, msgpack, protocol, end-to-end over a real WS
flutter analyze && flutter test # app: lints, widget behaviour
```

Both are the CI gate — neither half of a release ships if either is red. After a
Gather desktop update, re-check the log regexes against a real log:

```sh
npx gather-app-bridge replay ~/Library/Logs/GatherV2/main.log
```

### Common Patterns

- Long explanatory doc comments at the top of each file, stating *why* rather
  than *what*, usually with the failure mode that forced the design. Match that
  register when adding files.
- JS: ESM, `node:` prefixed builtins, no transpilation, no framework.
- Dart: sealed classes with exhaustive `switch`, `ChangeNotifier` for state, no
  state-management package.

### Releasing

Bump `version` in `package.json`, commit, then tag. The tag is the single source
of truth for both halves:

```sh
git tag -a v0.2.0 -m "gather-app-bridge 0.2.0"
git push --tags
```

See `.github/AGENTS.md` and the README's Releasing section for the constraints
(the workflow filename is load-bearing for npm; signing is manual on purpose).

## Dependencies

### Internal

- `lib/` → `packages/gather_events` (path dependency) → the JSON emitted by
  `bridge/lib/events.js`.

### External

- **Bridge:** none. Node 22+ builtins only (`node:http`, `WebSocket`, `node:crypto`, `node:zlib`).
- **App:** `flutter_local_notifications`, `mobile_scanner` (7.x),
  `flutter_secure_storage` (11.x), `shared_preferences`, `firebase_core`,
  `firebase_messaging`. **All Swift Package Manager — no CocoaPods.**
  `flutter_secure_storage` is pinned to 11.x for exactly that reason: 9.x has no
  SPM support and pulls the whole project back onto pods.
- **Runtime target being read:** Gather's own game server, from both halves. The
  Gather V2 Electron desktop client's `~/Library/Logs/GatherV2/main.log` is read
  for event reminders only, and even that is derivable from state.
